# Деплой OpenSaaS в Timeweb Cloud

**Сначала прочитай `DEPLOY.md` в корне репозитория (раздел «Три правила»).** Без API-ключа
ничего не создавай; MCP-коннектор Timeweb не используй: он создаёт базу без публичного IP,
и приложение не может к ней подключиться. Всё создаёт только `deploy_timeweb.py deploy`.

Цель: человек присылает API-ключ Timeweb → ты за ~10 минут поднимаешь БД и приложение,
отдаёшь ссылку и логин/пароль админа, а затем объясняешь, какие ENV добавить для продакшна
(SMTP и Робокасса) и где их взять.

Вся работа с API сделана в скрипте `deploy_timeweb.py` рядом с этим файлом. Не повторяй
вызовы API вручную, запускай скрипт: в нём уже учтены все подводные камни (см. конец файла).

Общайся с человеком **по-русски и простыми словами**, без жаргона. Показывай этапы по ходу работы.

## Архитектура (чтобы понимать, что деплоишь)

- Корневой `Dockerfile` собирает **всё в один контейнер**: Next.js (фронт) + FastAPI/gunicorn
  (бэк) + nginx на порту `10000`, всем управляет supervisord.
- При старте `start.sh` сам делает `alembic upgrade head` и `scripts/create_admin.py`
  (создаёт админа из `ADMIN_EMAIL`/`ADMIN_PASSWORD` и тарифы).
- Регистрация работает сразу после деплоя: без SMTP подтверждение email выключено, от ботов
  защищает встроенная ALTCHA (без ключей). Почта включается позже, см. шаг 5.1.
- Нужна внешняя PostgreSQL → создаём управляемую БД Timeweb.
- Это единственный способ сборки и деплоя. `docker-compose*.yml` нужны только для запуска на
  своём компьютере (`LOCAL_SETUP.md`). Пошаговая инструкция: `DEPLOY.md` в корне.

## Шаг 0. Что человек делает сам (API это не умеет)

Если чего-то нет, попроси человека сделать это и дождись ответа:

1. **Форк/копия репозитория** в свой GitHub-аккаунт.
2. **Регистрация в Timeweb Cloud** (https://timeweb.cloud) и **пополнение баланса**.
   Деньги списываются почасово; для теста хватит нескольких сотен рублей.
3. **API-ключ**: панель Timeweb → слева «API и Terraform» (или профиль → «API и Terraform»)
   → «Создать токен» → права полные, срок любой → скопировать ключ и прислать в чат.
4. **Подключить GitHub к Timeweb**: панель → App Platform → «Создать» → значок **GitHub** →
   авторизоваться и дать доступ к репозиторию (all repositories или конкретный).
   Дальше форму **не заполнять и «Заказать» не нажимать**, достаточно, чтобы появился аккаунт.

## Шаг 1. Подготовка

Ключ из чата передавай скрипту **только через переменную окружения** в той же команде.
**Никогда** не записывай ключ в файлы репозитория, `.env`, коммиты, PR или комментарии.

```bash
# macOS / Linux / Git Bash
TIMEWEB_TOKEN='<ключ>' python3 .claude/skills/deploy-timeweb/deploy_timeweb.py check
```
```powershell
# Windows PowerShell
$env:TIMEWEB_TOKEN='<ключ>'; python .claude/skills/deploy-timeweb/deploy_timeweb.py check
```

Общие флаги (`--repo`, `--name`, `--branch`, `--app-id`) ставятся **до** команды:
`deploy_timeweb.py --repo owner/name check`.

`check` проверяет ключ, баланс, подключённый GitHub, видимость репозитория и последний коммит.
Репозиторий определяется из `git remote origin`; если не вышло, добавь `--repo owner/name`.
Ветка по умолчанию `main` (`--branch` для другой). Скрипт сам объясняет, что сделать при ошибке.
Перескажи это человеку простыми словами.

## Шаг 2. Цена и согласие (обязательно)

```bash
TIMEWEB_TOKEN='<ключ>' python3 .claude/skills/deploy-timeweb/deploy_timeweb.py plan
```

Покажи человеку: что будет создано, цену в месяц и в час, и на сколько дней хватит баланса.
По умолчанию регион **Москва** (`ru-3`), приложение 1 CPU / 2 ГБ, БД 1 CPU / 1 ГБ, плюс
публичный IP БД. Итого около 1500 ₽ в месяц, списывается почасово.

Одним сообщением спроси:
1. Согласен ли он на эти расходы?
2. **На какой email сделать администратора сайта?** Это логин в админку сайта. На этот адрес
   будут приходить письма, например для сброса пароля. Пароль сгенерируем сами и покажем в конце.

**Не запускай `deploy` без явного «да».** Флаг `--yes` означает, что согласие получено.

## Шаг 3. Деплой

```bash
TIMEWEB_TOKEN='<ключ>' python3 .claude/skills/deploy-timeweb/deploy_timeweb.py deploy --email <email_админа> --yes
```

Занимает 5–12 минут: БД стартует 5–7 минут, сборка идёт около 4 минут. Сборка одна:
адрес сайта бэкенд берёт из заголовка `Host` запроса, поэтому передеплой после выдачи
домена не нужен. Скрипт печатает этапы. Запускай его с большим таймаутом
(≥ 25 минут) или в фоне и пересказывай человеку этапы по мере прохождения:

1. Проверка ключа и GitHub.
2. Создание PostgreSQL, ожидание запуска.
3. Включение публичного IP для БД.
4. Повторная выдача прав пользователю БД (обход бага Timeweb).
5. Создание приложения со всеми ENV и ожидание сборки.
6. Проверка `https://<домен>/health`.

Скрипт идемпотентен: если он оборвался, запусти ту же команду ещё раз, он продолжит с
существующими БД и приложением. Секреты (пароли БД и админа, `SECRET_KEY`) сохраняются
**вне репозитория**, в `~/.opensaas-timeweb/<имя>.json`.

Если деплой упал, смотри логи: `... deploy_timeweb.py logs -n 150`. Диагностируй, исправь и
сделай `redeploy`. Команда `status` показывает состояние приложения, БД и последних деплоев.

## Шаг 5. Что добавить для продакшна

Переменные добавляются командой `set-env`, удаляются командой `unset-env`. Обе ждут
перезапуска приложения (около 4 минут):

```bash
TIMEWEB_TOKEN='<ключ>' python3 .claude/skills/deploy-timeweb/deploy_timeweb.py set-env KEY1=value1 KEY2=value2
TIMEWEB_TOKEN='<ключ>' python3 .claude/skills/deploy-timeweb/deploy_timeweb.py unset-env KEY1 KEY2
```

Значения с пробелами бери в кавычки: `"SMTP_FROM_NAME=Мой сервис"`. Общие флаги (`--repo`,
`--name`, `--app-id`) ставятся **до** команды: `deploy_timeweb.py --repo owner/name set-env ...`.

### 5.1 Почта (SMTP): как работает и как включить

**Как устроено в коде.** Почта включается автоматически, как только заданы `SMTP_USER` и
`SMTP_PASSWORD` (`settings.email_enabled`):

| | Почта **не** настроена (после деплоя) | Почта настроена |
|---|---|---|
| Регистрация | сразу в кабинет, без кода | код из письма (6 цифр) |
| Сброс пароля | недоступен, на странице подсказка «обратитесь к администратору» | ссылка в письме |
| Баннер «подтвердите email» | не показывается | показывается неподтверждённым |
| API-ключи | создаются без подтверждения | только после подтверждения email |

**Главная ловушка Timeweb.** App Platform по умолчанию **закрывает исходящие почтовые порты
25, 465, 587 и 2525** (защита от спама). Если задать SMTP, пока порт закрыт, сайт будет
требовать код, а письмо не уйдёт, и **новые пользователи застрянут на экране кода**. Поэтому
порядок всегда такой: **сначала поддержка открывает порт, потом SMTP, потом `test-email`**.

Отправь человеку этот блок (подставь App ID из вывода `deploy`/`status`):

> 📬 **Как подключить почту**
>
> Сейчас регистрация работает без подтверждения email. Когда подключим почту, появятся:
> - **код подтверждения при регистрации.** Так в базе не будет чужих и несуществующих адресов;
> - **восстановление пароля по ссылке из письма.** Пользователи смогут сами вернуть доступ;
> - основа для писем пользователям (уведомления, рассылки).
>
> **Шаг 1. Попросите Timeweb открыть почтовый порт.** Timeweb по умолчанию закрывает его, чтобы
> с серверов не рассылали спам. Напишите в чат поддержки в панели Timeweb:
>
> ```
> Здравствуйте! Прошу открыть исходящий порт 587 (SMTP) для приложения
> App Platform ID <APP_ID>. Он нужен для отправки писем подтверждения регистрации
> и сброса пароля пользователям моего сайта. Массовых рассылок не будет.
> ```
>
> **Шаг 2. Получите пароль приложения для почты**, от которой будут уходить письма.
> - **Gmail:** включите двухэтапную проверку
>   (https://myaccount.google.com/signinoptions/twosv), затем создайте пароль на
>   https://myaccount.google.com/apppasswords (16 букв). Если Google пишет «Настройка
>   недоступна», значит, не включена двухэтапная проверка.
> - **Яндекс:** id.yandex.ru → «Безопасность» → «Пароли приложений» → «Почта». В настройках
>   Яндекс Почты → «Почтовые программы» включите доступ по IMAP/SMTP с паролями приложений.
>
> Обычный пароль от почты не подойдёт, нужен именно пароль приложения.
>
> **Шаг 3. Когда поддержка ответит, что порт открыт, пришлите мне сообщение:**
>
> ```
> Подключи почту. Timeweb открыл порт 587.
> Почта: ящик@gmail.com
> Пароль приложения: xxxx xxxx xxxx xxxx
> Имя отправителя: Название моего сервиса
> ```

**Когда человек прислал данные:**

1. Пропиши переменные (пароль приложения без пробелов; порт всегда **587**, STARTTLS, с 465
   этот код не работает):
   ```
   set-env SMTP_HOST=smtp.gmail.com SMTP_PORT=587 SMTP_USER=ящик@gmail.com \
     SMTP_PASSWORD=парольприложения SMTP_FROM_EMAIL=ящик@gmail.com \
     "SMTP_FROM_NAME=Название" SMTP_USE_TLS=true
   ```
   Для Яндекса `SMTP_HOST=smtp.yandex.ru`, для Mail.ru `smtp.mail.ru`. `SMTP_FROM_EMAIL`
   должен совпадать с `SMTP_USER`.
2. **Обязательно проверь:** `test-email`. Команда входит на сайт админом и отправляет письмо
   на email админа, а ошибку SMTP показывает сразу, без чтения логов.
   - `OK`: попроси человека найти письмо «Проверка почты» (в том числе в «Спаме»). Готово.
   - `Timed out connecting ... port 587`: порт ещё закрыт. **Сразу верни сайт в режим без
     почты:** `unset-env SMTP_USER SMTP_PASSWORD`, иначе новые пользователи застрянут на экране
     кода. Попроси человека написать в поддержку Timeweb (текст выше) и повтори после ответа.
   - `SMTPAuthenticationError` / `535`: неверный пароль приложения или не включён доступ
     по SMTP. Также сделай `unset-env SMTP_USER SMTP_PASSWORD` и попроси новый пароль.
3. Не говори «почта работает», пока `test-email` не вернул `OK`.

Если поддержка отказала, не оставляй SMTP включённым. Сайт полноценно работает и без почты.

### 5.2 Робокасса (приём платежей)

**Правило: подключаем сразу боевые пароли. Тестовые пароли никогда не запрашиваем** и
тестовый режим не включаем (`ROBOKASSA_TEST_MODE=false` ставится при деплое).

```
set-env ROBOKASSA_MERCHANT_LOGIN=идентификатор_магазина \
  ROBOKASSA_PASSWORD1=боевой_пароль_1 ROBOKASSA_PASSWORD2=боевой_пароль_2 \
  ROBOKASSA_TEST_MODE=false
```

Где взять:
1. Зарегистрироваться на https://robokassa.com (ИП, ООО или самозанятый) и в личном кабинете
   → «Мои магазины» → **создать магазин** (указать домен сайта). Если у человека уже есть
   магазин, привязанный к другому работающему сайту, предложи создать отдельный: адреса
   Result/Success/Fail у магазина одни на всех.
2. В магазине → **«Технические настройки»** (верхний блок, **не** «Параметры тестовых платежей»):
   - **Идентификатор магазина** → `ROBOKASSA_MERCHANT_LOGIN`;
   - **Алгоритм расчёта хеша: MD5** (код подписывает MD5, с другим алгоритмом оплата не пройдёт);
   - **Пароль #1** и **Пароль #2**: «Сгенерировать», сохранить у себя → `ROBOKASSA_PASSWORD1` / `ROBOKASSA_PASSWORD2`;
   - **Result URL**: `https://<домен>/api/v1/webhooks/robokassa`, метод **POST**;
   - **Success URL** и **Fail URL**: `https://<домен>/billing`, метод **GET** (у Fail URL
     по умолчанию бывает POST — переключить);
   - «Сохранить».

Сообщение, которое человек может прислать в чат:
```
Подключи Робокассу.
Идентификатор магазина: ...
Пароль #1: ...
Пароль #2: ...
```

**Проверка после `set-env`** (без оплаты): зарегистрируй тестового пользователя через API
(капча решается как в `modules/auth/altcha.py`), вызови `POST /api/v1/billing/subscribe`
с `{"plan_id": ..., "provider": "robokassa"}` и открой `payment_url`. Если Робокасса показывает
страницу выбора способа оплаты, логин и пароль #1 верны. Ошибка «неверные параметры» /
«магазин не найден» — неверный идентификатор или пароль #1, либо в магазине не MD5.
Пароль #2 проверяется только реальной оплатой (подпись Result URL): попроси человека оплатить
самый дешёвый тариф и убедись, что подписка стала активной (`/billing`), затем при желании
сделать возврат в кабинете Робокассы.

Цены тарифов можно поменять через ENV (иначе будут значения по умолчанию):
`PLAN_BASIC_NAME`, `PLAN_BASIC_PRICE` (990), `PLAN_BASIC_FEATURES` (через запятую),
и аналогично `PLAN_PRO_*` (2990).

### 5.3 Свой домен (по желанию)

Панель → App Platform → приложение → «Домены» → добавить домен, у регистратора прописать
A-запись на IP приложения (он виден в панели). Затем:
```
set-env APP_URL=https://мойдомен.ру
```
Это необязательно: без `APP_URL` ссылки в письмах ведут на тот домен, с которого пришёл
человек. С `APP_URL` все письма будут вести на основной домен.
После смены домена обнови Result URL, Success URL и Fail URL в Робокассе.

### Что трогать не нужно
- `ALTCHA_ENABLED`: защита от ботов включена по умолчанию, ключи не нужны (подпись задач
  делается от `SECRET_KEY`). Выключать (`ALTCHA_ENABLED=false`) стоит только для отладки.
- `REDIS_URL`: без него лимиты запросов хранятся в PostgreSQL. Это штатный режим.
- `STRIPE_*`: это заготовка, она не активна.
- Предупреждение в логах `bcrypt has no attribute '__about__'` / `(trapped) error reading bcrypt version`
  безвредно. Это несовместимость версий passlib и bcrypt, пароли работают нормально.

## Подводные камни (уже учтены в скрипте, пригодятся при ручной отладке)

- API App Platform: поле репозитория называется `repository_id` (не `git_repository_id`);
  `build_cmd` и `run_cmd` обязательны, даже пустые; `framework: "docker"` включает сборку
  из корневого `Dockerfile`; `type: "backend"`.
- Тарифы: `GET /presets/apps` (`backend_presets`) и `GET /presets/dbs`. Москва = `ru-3`.
  Для приложения берём 2 ГБ RAM: сборке Next.js 1 ГБ может не хватить.
- У БД в `ru-3` нет приватной сети с App Platform, поэтому публичный IP обязателен:
  `PATCH /databases/{id}` с `{"is_enabled_public_network": true}`. Это стоит около 200 ₽ в месяц.
- **Баг прав**: пользователь `gen_user` создаётся в статусе `granting_privileges`, и даже после
  перехода в `created` приложение может получать `User does not have CONNECT privilege`.
  Лечится повторным `PATCH /databases/{id}/admins/{admin_id}` с теми же `privileges` и
  `instance_id`, затем `redeploy`.
- `DATABASE_URL` должен быть в формате `postgresql+asyncpg://...`. Пароль БД делаем только из
  букв и цифр: `%` ломает configparser в alembic.
- `PATCH /apps/{id}` с `envs` **заменяет весь набор** переменных и сам запускает передеплой.
  Поэтому сначала читаем текущие ENV и сливаем их с новыми (так и делает `set-env`).
- В production бэкенд падает при старте, если `SECRET_KEY` короче 32 символов или равен
  дефолтному, если `ADMIN_PASSWORD` дефолтный или если в `CORS_ORIGINS` есть `*`.
- Логи: `GET /apps/{id}/logs` → `app_logs` (массив строк). Деплои: `GET /apps/{id}/deploys`,
  статусы: `building` → `prepare` → `container_started` → `success`/`failure`.
- **Почтовые порты закрыты**: App Platform по умолчанию блокирует исходящие 25, 465, 587 и 2525.
  Симптом в логах: `SMTPConnectTimeoutError: Timed out connecting to smtp.gmail.com on port 587`.
  Открывает только поддержка Timeweb (шаг 5.1). Проверка: `test-email`.
- Технический домен вида `<owner>-<repo>-xxxx.twc1.net` становится известен только после
  создания приложения, поэтому `APP_URL` не задаём (см. `backend/public_url.py`). SSL-сертификат может выпускаться 1–3 минуты.
