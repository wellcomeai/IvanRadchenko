# Инструкции для AI-агентов (Codex, Claude Code и др.)

## Деплой в Timeweb Cloud

Если человек просит задеплоить проект в Timeweb (таймвеб) или присылает API-ключ Timeweb,
выполняй по шагам [`DEPLOY.md`](DEPLOY.md) (это единственный способ деплоя) и
инструкцию `.claude/skills/deploy-timeweb/SKILL.md` и используй скрипт
`.claude/skills/deploy-timeweb/deploy_timeweb.py`. Через тот же скрипт добавляются ENV
для продакшна: SMTP, Робокасса, свой домен.

**Важно:** без API-ключа Timeweb ничего не создавай — сначала попроси ключ. MCP-коннектор /
инструменты Timeweb для создания базы и приложения **не используй**: база получается без
публичного IP, и приложение не может к ней подключиться. Всё создаёт только скрипт.

Кратко:
1. `check`: проверить ключ, баланс и подключённый GitHub.
2. `plan`: показать цену и получить явное согласие, спросить email администратора.
3. `deploy --email <email> --yes`: создать БД и приложение, выдать ссылку и пароль админа.
4. Первое сообщение после деплоя — строго по шаблону из SKILL.md (шаг 4): что уже работает,
   расходы, и блок «Как подключить почту» с готовым текстом для поддержки Timeweb.
5. `set-env KEY=VALUE ...`: добавить SMTP и Робокассу (только боевые пароли, тестовые не запрашиваем). После SMTP обязательно `test-email`;
   если порт закрыт — `unset-env SMTP_USER SMTP_PASSWORD` (иначе регистрация застрянет на коде).

Регистрация работает сразу после деплоя: без SMTP подтверждение email выключено, от ботов
защищает встроенная ALTCHA (без ключей и внешних сервисов). Timeweb по умолчанию закрывает
исходящие почтовые порты (25, 465, 587, 2525) — их открывает поддержка.

API-ключ передавай только через переменную окружения `TIMEWEB_TOKEN` и никогда не сохраняй
его в файлы репозитория.

## Наставник: объяснить проект и помочь доработать

Если человек просит объяснить, как работает проект («объясни, как это работает», «что это
такое», «с чего начать», «я не программист»), хочет понять, что на нём можно построить, или
просит помочь с доработкой, следуй инструкции `.claude/skills/opensaas-mentor/SKILL.md`:
объясняй простыми словами на аналогиях, опирайся на реальный код, веди по шагам и не меняй
код без явного согласия.

Документация по коду: `docs/` и `CLAUDE.md` в `backend/` и `frontend/`.
