# Деплой OpenSaaS в Timeweb Cloud: пошаговая инструкция для AI-агента

Это **единственный** способ деплоя проекта. Других путей сборки нет: корневой `Dockerfile`
собирает всё в один контейнер (Next.js + FastAPI + nginx), Timeweb App Platform собирает его
из GitHub, база — управляемая PostgreSQL Timeweb. Всю работу с API делает скрипт
`.claude/skills/deploy-timeweb/deploy_timeweb.py`. **Не вызывай API Timeweb вручную.**

Выполняй шаги строго по порядку. Каждую команду запускай из корня репозитория.
Общайся с человеком по-русски и простыми словами.

## ⛔ Три правила (нарушение = сломанный деплой)

1. **Нет API-ключа Timeweb в сообщении человека — ничего не создавай.** Первым делом попроси
   ключ (строка, начинается с `eyJ`). Не создавай базу и приложение «пока без ключа».
2. **Не используй MCP-коннектор / встроенные инструменты Timeweb** (create_database,
   create_app и т.п.), даже если они подключены. Они создают базу **без публичного IP** и
   без повторной выдачи прав — приложение потом не может подключиться к базе
   (`public_ip: null`, падение на миграциях). Базу и приложение создаёт **только** скрипт
   `deploy_timeweb.py` командой `deploy`.
3. **Не включай публичный IP, не прописывай `DATABASE_URL` и не создавай ресурсы руками** —
   скрипт делает это сам (создание БД → публичный IP → права пользователя → приложение с
   `DATABASE_URL`). Если что-то уже создано не скриптом, попроси человека удалить это в
   панели Timeweb и запусти скрипт заново с новым `--name`.

---

## Что нужно получить от человека до начала

1. **API-ключ Timeweb** (длинная строка, начинается с `eyJ`).
2. **Явное согласие на расходы** (~1500 ₽/мес, списываются почасово).
3. **Email администратора сайта** (логин в админку).
4. **Ветка** для деплоя. Если не сказано — `main`.

Если ключа нет, попроси человека:
- зарегистрироваться на https://timeweb.cloud и пополнить баланс;
- создать ключ: панель → «API и Terraform» → «Создать токен» → полные права → прислать в чат;
- подключить GitHub: панель → App Platform → «Создать» → значок GitHub → дать доступ к
  репозиторию. Форму дальше не заполнять, «Заказать» не нажимать.

⚠️ Ключ **никогда** не записывай в файлы, коммиты, PR и комментарии. Только переменная
окружения `TIMEWEB_TOKEN` в той же команде.

## Шаг 1. Придумать уникальное имя проекта

Каждый новый деплой создаёт **новое** приложение и **новую** базу. Имя должно быть
уникальным, иначе скрипт продолжит работу со старым приложением с тем же именем.
Делаем имя из даты и времени:

```bash
NAME=opensaas-$(date +%m%d%H%M)
echo $NAME
```

Пример результата: `opensaas-10021406`. **Запомни это имя** — оно нужно во всех следующих
командах (флаг `--name`). База будет называться `<имя>-db`.

## Шаг 2. Проверка ключа, баланса и GitHub

```bash
export TIMEWEB_TOKEN='<ключ>'
python3 .claude/skills/deploy-timeweb/deploy_timeweb.py --name <имя> --branch main check
```

Флаги `--name`, `--branch`, `--repo`, `--app-id` всегда пишутся **до** команды
(`check`, `plan`, `deploy` и т.д.).

Ожидаемый вывод:
```
==> API-ключ рабочий
    Баланс: 102.32 RUB, ...
==> GitHub подключён (Owner), репозиторий Owner/Repo виден Timeweb
    Ветка main: последний коммит cebbc71
OK: можно запускать plan / deploy
```

Если последней строки `OK` нет — перескажи человеку текст ошибки из вывода (скрипт сам пишет,
что сделать) и жди, пока он исправит. Дальше не иди.

Ожидаемый вывод (в конце):

  • Приложение  1 CPU / 2 ГБ RAM / 30 ГБ — 810 ₽/мес

- Если человек **ещё не согласился** на расходы или **не дал email** — покажи ему цену и

- Если баланса хватит меньше чем на 1–2 дня — обязательно предупреди человека в итоговом
  сообщении, что надо пополнить баланс.

## Шаг 4. Деплой

```bash
python3 -u .claude/skills/deploy-timeweb/deploy_timeweb.py --name <имя> --branch main \
  deploy --email <email_админа> --yes 2>&1
```

Занимает **10–15 минут**. Обязательно:
- запускай с таймаутом **не меньше 25 минут** или в фоне;
- если команда ушла в фон — периодически читай её вывод и коротко пиши человеку, на каком
  этапе работа. **Не останавливай процесс** и не запускай второй параллельно.

Этапы в выводе (по порядку):
```
==> Проверяю API-ключ, баланс и GitHub
==> Создаю PostgreSQL «<имя>-db»
    статус БД: starting ... статус БД: started  (~7 минут)
==> Включаю публичный IP для БД
==> Повторно выдаю права пользователю gen_user
==> Создаю приложение App Platform «<имя>»
==> Жду сборку и запуск (обычно 4–6 минут)
    деплой: building → prepare → container_started → success
==> Проверяю, что сайт отвечает снаружи
    GET https://....twc1.net/health → 200
============================================================
ГОТОВО
  Сайт:            https://xxxx.twc1.net
  Админ логин:     <email>
  Админ пароль:    <пароль>
  App ID:          263821   DB ID: 4215663
  Webhook Робокассы (Result URL): https://xxxx.twc1.net/api/v1/webhooks/robokassa
============================================================
```

Успех = есть блок `ГОТОВО` и код выхода 0. Ссылку, пароль и App ID бери **только из этого
блока**, ничего не придумывай.

### Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| Команда оборвалась (сеть, таймаут) | Запусти **ту же самую** команду шага 4 ещё раз. Скрипт продолжит с уже созданными БД и приложением. |
| `деплой: failure` | `python3 .claude/skills/deploy-timeweb/deploy_timeweb.py --name <имя> logs -n 150`, найди ошибку, исправь, затем `... --name <имя> redeploy` |
| `/health` не 200 сразу после `success` | Подожди 1–3 минуты (выпускается SSL-сертификат) и проверь `... --name <имя> status` |
| `CONNECT privilege` в логах | `... --name <имя> redeploy` (известный баг Timeweb, скрипт уже обходит его) |

Секреты (пароли БД и админа) скрипт сохраняет вне репозитория: `~/.opensaas-timeweb/<имя>.json`.

## Команды после деплоя

Во всех командах указывай то же `--name <имя>`, что и при деплое.

```bash
S=.claude/skills/deploy-timeweb/deploy_timeweb.py
python3 $S --name <имя> status                       # состояние приложения, БД, деплоев
python3 $S --name <имя> logs -n 150                  # логи приложения
python3 $S --name <имя> redeploy                     # пересобрать и перезапустить
python3 $S --name <имя> set-env KEY=VALUE ...         # добавить ENV (SMTP, Робокасса, домен)
python3 $S --name <имя> unset-env KEY ...             # удалить ENV
python3 $S --name <имя> test-email                   # проверить почту после SMTP
```

Как подключать почту, Робокассу и свой домен — `.claude/skills/deploy-timeweb/SKILL.md`, шаг 5.

После деплоя каждый новый коммит в выбранную ветку сам выкатывается на сайт примерно за
4 минуты. Отдельно ничего запускать не нужно.
